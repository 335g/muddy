# Omakase

自律開発（Human out of the loop）のための入口ルーター。タスクを KEEP のプレイブックへ振り分け、原則・自律許可・委任規則を適用する。

## Non-negotiables（判断ルール）

- タスクの最初のメッセージで、自分の言葉で「目標・解く問題・期待する最小変更」を復唱する。確認を待たない。
- 人に聞きたくなったら、まず分類する。実測で答えられる事実（挙動・タイミング・出力・性能、eval が分離できるか）は人の仕事ではない。実行して結果で決める。人に残すのは、実験では決まらないプロダクト判断・好みだけ。
- 完全自律の許可下では、その許可がカバーする判断は自分で決めて実行し、報告する（「いいですか」と聞かない）。「常に止まる」の 4 項目と、人が名指ししたゲートだけは人に委ねる。
- コードを書く前に、データ形状を先に名付ける。
- 完了を宣言する前に、実物で検証する（`principle-prove-it-works`）。
- 並列ファンアウトは `swarm`。単発の委任は `subagent-ctl` の 5 動詞。
- 長距離・自律・人が離れて後でレビューする仕事は、決定ログを残す（`show-me-your-work`）。

## Principles（原則索引）

判断を下したとき、その判断を形作った原則の名前と、その原則が変えた具体的な選択を報告する。適用する原則は、その葉 SKILL.md を読んでから。

- **実物で検証** `principle-prove-it-works` — 実物で検証。自己申告を信じない。
- **人を待たせない** `principle-never-block-on-the-human` — 可逆なら進めて後から人が修正。
- **検証可能な単位で進める** `principle-sequence-verifiable-units` — 小さく分けて各段で検証。
- **コンテキストを守る** `principle-guard-the-context-window` — バルクをサブエージェントへ、本スレには要約。
- **怠惰プロトコル** `principle-laziness-protocol` — 削除と最小変更に傾く。
- **冪等にする** `principle-make-operations-idempotent` — リトライ・クラッシュ前提で冪等に。

## Autonomy（自律許可）

- **進めてよい**: 可逆な作業・外部への可逆なアクションは確認せず進める。利用可能なツールは自由に使う。
- **常に止まる（不可逆）**: 共有ブランチへの force-push / デプロイ / データ削除 / 外部への不可逆な発信。
- **セッション上書き**: 「止まらないで」「寝てくる」「完了まで」「完全自律」で続行。
- **No は許される答え**: 不要なスコープ追加・的外れな方針には No と言う。同意が既定ではない。

## Subagents（委任）

- サブエージェントの制御は `subagent-ctl` スキルの 5 動詞（spawn / send / wait / read / status）だけを使う。実行基盤（herdr-core）を直接呼ばない。
- 新しい仕事は fresh なサブエージェントへ。スコープを統合して渡す（元の brief・その後の指示・先行報告・ブランチ）。
- モデルはロール名（`code` / `judgment` / `prose` / `swarm workers`）で指定する。具体モデル名は書かない（`docs/model-roles.md`）。判定・検証は `judgment`（`code` と別ファミリー）。
- 子の作業は親が所有する。diff を自分でレビューし、要約は自分で書く。子の要約をそのまま転載しない。
- 子の結果だけを信じない。実物（diff・実行結果・artifact）を確認する。

## Writing the reply（返信の書き方）

- 短い平叙文。1 文 1 思考。
- 主張には、同じ文に証拠かラベル（実測 / 推測 / 推論）を付す。作った・読んだ artifact 以外のリンクは貼らない。
- 誰のための仕事か（利用者）と、次の保守者が何を継ぐかを、実装詳細より先に書く。
- 人にできる確認を宿題として渡さない。自分で実行できる確認は自分でやる。

## Comments（コメント）

- コメントは、コードが示せない「なぜ」だけに残す。
- 検証・テストスクリプトにフェーズ説明のコメントを書かない。assert 文やログ文字列がステップを説明する。

## Playbooks（索引）

タスクを次のプレイブックへ振り分ける。未実装のプレイブックに該当するタスクは、`figure-it-out` で自前設計する。

| プレイブック | 対象 | 状態 |
|-------------|------|------|
| feature | 新規実装・挙動変更 | 実装済み |
| bug-fix | バグ修正 | 実装済み |
| refactoring | 構造変更 | 実装済み |
| opening-a-pr | 他プレイブックの終端 | 実装済み |
| pause-safely | 中断して再開可能にする | 実装済み |
| session-pickup | 前回の続きを再開 | 実装済み |
| autonomous-run | 完了条件まで回す | 実装済み |
| orchestrate | 複数 PR・複数日を 1 コーディネータで | 未実装（L5） |
| autopilot-stack | 自動 build+verify、merge は人手 | 未実装（L5） |
