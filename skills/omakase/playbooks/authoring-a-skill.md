# Authoring a skill（スキルの作成・変更）

スキルの文章は、将来の全エージェントへの指示になる。書き散らしは許さない。

1. 変更の意図を 1 文にする。「どの判断が、どう変わるか」。変わらないなら書かない。
2. `SKILL.md` を書く。frontmatter は `name`（ディレクトリ名と同じ英数スラッグ）と `description`（何をするかではなく、いつ使うか）。
3. 検証する。`node scripts/check-skills.mjs` が、frontmatter・本文が参照するパス・プレイブック索引を見る。
4. 判断を要する規則なら、先に構造で防げないか考える。lint・スクリプト・メタデータで防げるものは、文章を増やさずそちらへ置く。文章は、判断が要るものだけに残す。
5. 挙動が変わる変更なら `eval` を回す。回さないときは、その理由を返信に 1 行書く。
6. `opening-a-pr` で PR を開く。スキル変更は必ず PR にする。main へ直コミットしない。

## 書くときの規則

- 迷ったら消す。判断を変えない文は要らない。
- 理由は、無いと誤解されるときだけ書く。それ以外は、してほしいことを書く。
- 他のスキルへはパスで委譲する。同じ指示を書き直さない。
- 具体モデル名を書かない。ロール名（`code` / `judgment` / `prose` / `swarm workers`）を使う。
- 一度踏んだ手順で、まだスキルになっていないものは、新しいスキルを提案する。

**返信**: 何を変えたかを 1 行、検証の結果、eval を回したか（回したなら TSV のパス）。
